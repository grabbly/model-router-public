Документация для подключения

Подключение к model-router

model-router — шлюз к языковым моделям, совместимый с OpenAI API. Подходит любая библиотека, которая умеет работать с OpenAI Chat Completions: достаточно сменить адрес, ключ и название модели. Какая модель ответит на самом деле, выбирает роутер. Если модель недоступна, он сам переключается на следующую.

Адрес
https://router.example.com/v1
Авторизация
Authorization: Bearer <ключ>
Метод
POST /v1/chat/completions

Подключение за 5 шагов

ШагЧто сделать
1Получите ключ проекта (pft_…) у владельца роутера и положите его в переменную окружения, например ROUTER_TOKEN. В код и в репозиторий ключ не кладите.
2В своём OpenAI-клиенте укажите адрес https://router.example.com/v1 и этот ключ.
3Вместо названия модели укажите тир: text-high, text-low и т. д. (какой выбрать).
4Добавьте в каждый запрос три заголовка: x-router-app, x-router-agent, x-router-session (как их заполнять). С 1 октября 2026 без них запрос не пройдёт.
5Отправьте тестовый запрос и проверьте заголовки ответа. Если пришёл x-router-warning: missing-metadata, какой-то из трёх заголовков не дошёл. Ответ 429 loop_detected не повторяйте автоматически (почему).

Быстрый старт

Замените $ROUTER_TOKEN на выданный вам ключ, а myproject — на название вашего проекта.

curl
curl -sS https://router.example.com/v1/chat/completions \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -H "x-router-app: myproject" \
  -H "x-router-agent: chat" \
  -H "x-router-session: conv-1842" \
  -d '{
    "model": "text-low",
    "messages": [{"role": "user", "content": "Привет!"}]
  }'
JavaScript · openai
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: process.env.ROUTER_TOKEN,
  baseURL: 'https://router.example.com/v1',
  // app и agent не меняются — задайте один раз
  defaultHeaders: { 'x-router-app': 'myproject', 'x-router-agent': 'chat' },
});

const res = await client.chat.completions.create(
  { model: 'text-high', messages: [{ role: 'user', content: 'Привет!' }] },
  // session — свой для каждого диалога или задачи
  { headers: { 'x-router-session': conversationId } },
);
console.log(res.choices[0].message.content);
Python · openai
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["ROUTER_TOKEN"],
    base_url="https://router.example.com/v1",
    default_headers={"x-router-app": "myproject", "x-router-agent": "chat"},

    model="text-high",

    extra_headers={"x-router-session": conversation_id},

Поддерживаются потоковые ответы ("stream": true, SSE) и обычный JSON. В поле model ответа приходит название тира, которое вы запросили, а не реальная модель.

Ключ доступа

Ключ выглядит так: pft_<id-проекта>.<подпись>. Он выдаётся на один проект и идентифицирует вас в роутере: по нему считаются лимиты и расход.

  • Передавайте его в Authorization: Bearer <ключ> или в X-API-Key: <ключ>.
  • Храните ключ только на сервере: в переменных окружения или менеджере секретов. Не встраивайте его в браузерный код или мобильное приложение.
  • Один ключ — один проект. Если нужен второй проект или отдельная среда, попросите отдельный ключ. Не передавайте свой ключ другим.

Выбор модели

Вместо реальной модели указывается тир, то есть нужная возможность. Роутер сам выбирает живую и быструю модель под этот тир. Если указать реальное имя модели, например gemini-…, запрос вернётся с ошибкой.

text-high-thinkЧат с обязательным рассуждением (MiniMax-M3.1-Flash-Preview, reasoning_effort по умолчанию medium; можно передать свой low…max)безопасный
text-lowБыстрые и дешёвые задачи: классификация, короткие ответы, рутинабезопасный

Актуальный список тиров всегда можно получить через GET /v1/models.

Тиры 18+ настраивать не нужно. Нужную системную инструкцию роутер добавляет сам. Если вы пришлёте своё system-сообщение, оно сохранится и объединится с инструкцией роутера. Чтобы отключить добавление для отдельного запроса, передайте заголовок x-router-no-overlay: 1. Администратор также может отключить оверлей для всего клиента целиком; в этом случае принудительно включить его на один запрос можно заголовком x-router-overlay: 1 (при одновременной передаче приоритет сохраняется за x-router-no-overlay).

Заголовки: кто и откуда

Каждый запрос к /v1/chat/completions передаёт три заголовка. По ним видно, какой проект, какой его агент и в рамках какого диалога или задачи отправил запрос. На этом построены защита от зацикливания (блокируется одна сессия, а не весь проект) и разбор расхода по агентам.

ЗаголовокЧто этоКак часто меняетсяПример
x-router-appВаш проект. Короткое постоянное имя, латиницей.никогдаmyproject
x-router-agentКакая часть проекта отправила запрос: бот, фоновый воркер, суммаризатор, распознавание картинок.одно значение на каждую роль в кодеchat, worker, summarizer, vision
x-router-sessionОдин диалог пользователя или одна задача агента. Все запросы этого диалога или задачи, включая все шаги вызова инструментов, идут с одним значением.новое значение на каждый диалог или задачуconv-1842, task-77
x-router-user(Опционально) ID конечного пользователя для раздельного учёта лимитов внутри проекта. Если не передан, берётся часть x-router-session до первого двоеточия (например, user-1:chat:123 → user-1).на каждого пользователяuser-1842, uuid-42

Правила

  • Не делайте новую сессию на каждый запрос. Тогда защита от зацикливания не увидит цикл, и ваш агент сможет израсходовать весь лимит проекта.
  • Не кладите в сессию личные данные: email, телефон, имя. Нужен внутренний непрозрачный id.
  • Если вы параллельно отправляете одинаковые запросы (замеры, пакетная обработка), давайте каждому свою сессию. Иначе 3 одинаковых запроса подряд в одной сессии сработают как цикл.
  • Допустимые символы: A–Z a–z 0–9 . _ : @ / -, не длиннее 128. Остальные символы роутер отбрасывает.
  • Как задать заголовки в OpenAI SDK: app и agent — один раз в defaultHeaders / default_headers; session — в каждом запросе (примеры выше).

С 1 октября 2026 заголовки обязательны. До этой даты запросы без них проходят, а в ответе приходит заголовок x-router-warning: missing-metadata. С 01.10 такой запрос получит ошибку 400 missing_metadata.

Инструменты и мышление

tools и tool_choice передаются в формате OpenAI и доходят до модели без изменений. tool_choice может быть строкой (auto, required, none) или объектом {"type":"function","function":{"name":"…"}}. Работают и потоковые ответы, и обычный JSON.

  • Передавайте историю вызовов целиком: сообщения assistant с tool_calls и ответы с ролью tool. Если оставить в истории только тексты ответов, модель начинает копировать прошлые ответы вместо того, чтобы вызвать инструмент.
  • У основной модели (MiniMax) мышление по умолчанию выключено, так она отвечает быстрее. Но когда в запросе есть tools, роутер его включает: без мышления модель часто игнорирует tool_choice. Если скорость важнее надёжного вызова инструментов, передайте thinking: {"type": "disabled"} (или reasoning_effort: "none"), и мышление останется выключенным. Сделать это поведением по умолчанию для всего клиента может администратор.
  • Мышление можно запросить в том формате, к которому привыкли. Роутер понимает все распространённые варианты и сам переводит их для модели. adaptive — модель сама решает, сколько думать; disabled — не думать.
ПолеВключитьВыключить
thinking (Anthropic, MiniMax){"type":"enabled"}, {"type":"adaptive"}, true{"type":"disabled"}, false
reasoning_effort (OpenAI)low, medium, highnone, minimal
reasoning (Responses API, OpenRouter){"effort":"high"}, {"enabled":true}{"enabled":false}
enable_thinking (Qwen, vLLM)truefalse
think (Ollama)true, "high"false
thinking_budget (Gemini, в extra_body.google.thinking_config)больше 0 или -10
  • Если прислано несколько полей, действует первое по таблице. Бюджеты (budget_tokens, thinking_budget) только включают или выключают мышление, сколько думать, модель решает сама.
  • Рассуждения модели в ответ не попадают: в content остаётся только сам ответ. Чтобы получить их в полях reasoning_content и reasoning_details, передайте заголовок x-router-reasoning: 1 или "include_reasoning": true в теле. В потоке рассуждение тогда идёт кадрами delta.reasoning_content. Без этого кадры, где модель только думает, приходят пустыми ({"delta":{"role":"assistant"}}), но не чаще раза в секунду: это признак, что модель работает.
  • Обрыв потока виден явно: если апстрим замолчал или закрыл поток, не закончив ответ, последним кадром приходит data: {"error":{"code":"upstream_stream_error" | "upstream_stream_incomplete", …}}, затем data: [DONE]. Такой ответ считайте неудачным, а не пустым.

Картинки

Картинка передаётся в формате OpenAI: частью content с типом image_url. Надёжнее всего вкладывать её прямо в запрос как data:-URI (base64).

JSON
{
  "model": "vision-high",
  "messages": [{
    "role": "user",
    "content": [
      { "type": "text", "text": "Что на фото?" },
      { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,/9j/4AAQ..." } }
    ]
  }]
}
  • Весь запрос вместе с картинками — до 20 МБ, одна картинка — до ~10 МБ.
  • Ужимать фото заранее не обязательно. Для локальных моделей роутер сам уменьшает картинку до 1024 px по длинной стороне.
  • Запасная локальная модель может ответить на английском, даже если вопрос задан по-русски: на английском она распознаёт заметно точнее. Если язык важен, переведите ответ на своей стороне.

Что приходит в ответе

Помимо обычного ответа OpenAI роутер добавляет свои заголовки:

ЗаголовокЗначение
x-pf-backendКакая модель пула реально ответила. Полезно записывать в свой лог.
x-pf-backend-modelНазвание этой модели у провайдера
x-router-warningmissing-metadata — в запросе не хватает обязательных заголовков
x-router-budgetexceeded; reason=… — лимит проекта превышен, ответила запасная модель (см. ниже)
x-router-loop, retry-afterПриходят вместе с ошибкой 429 loop_detected или 429 rate_limited: какое правило сработало и сколько секунд ждать
x-router-context-lengthОкно контекста (в токенах) модели, которая реально обслужила запрос. Нет заголовка — окно этой модели неизвестно. Минимальное окно по каждому тиру — поле context_length_min в GET /v1/models

Лимиты и защита

Защита от зацикливания

Роутер следит за каждой сессией отдельно, то есть за сочетанием app + agent + session. Сессия блокируется на 10 минут по правилам volume и repeat. Правило rate не блокирует: это ограничение темпа.

ПравилоПорогЧто ловит
rate> 40 запросов за 5 мин (для x-router-agent: worker — > 120)слишком частые запросы. Ответ 429 rate_limited с Retry-After — через сколько секунд в окне освободится место; после паузы можно повторить
volume> 3 млн входных токенов за 10 минна каждом шаге пересылается огромный контекст
repeat3 одинаковых сообщения подрядагент ходит по кругу (запрос с другим max_tokens считается другим: повтор обрезанного ответа с большим пределом — не цикл; результаты тулов с разными tool_call_id — тоже разные сообщения)

Картинки в base64 при подсчёте объёма не раздувают счёт. Блокируется только одна сессия, остальные сессии проекта работают как обычно.

Не повторяйте запрос после 429 loop_detected. Это сигнал остановить цикл агента, а не временный сбой. Автоматический повтор только продлит блок.

Лимит на основную модель

На основную модель (MiniMax) у каждого проекта есть лимит токенов в сутки и в час, а также могут действовать раздельные лимиты на каждого пользователя. Токены считаются с учётом кэша промпта со скидкой (кэшированная часть обходится дешевле), сутки и часы — по UTC. Свой лимит можно уточнить у владельца роутера.

Когда лимит превышен, ошибки нет: запрос уходит на запасную модель тира, а в ответе приходит x-router-budget: exceeded; reason=…. Возможные значения reason:

  • user-hour или user-day — исчерпан часовой или суточный лимит конкретного пользователя;
  • tenant-hour или tenant-day — исчерпан часовой или суточный лимит вашего проекта;
  • provider-quota — исчерпан реальный остаток квоты у апстрим-провайдера (MiniMax Token Plan, ≤5%);
  • global-day или cycle — исчерпана общая норма роутера на сегодня или на месяц.

Ошибка 503 budget_exceeded возникает, если у тира не осталось доступных запасных моделей или они вернули ошибку. В тире text-high локальной 7B нет совсем: после MiniMax идут облачные Gemini/Claude, затем flash-lite и deepseek. Если при превышенном лимите ни одна из них не ответила, приходит 503 budget_exceeded.

Квота по запросу

Если проекту нужно динамически управлять лимитами токенов на основную модель MiniMax (например, пересчитывать лимит по количеству активных пользователей и их тарифным планам), клиентский портал может запрашивать выделение квоты напрямую через API.

Как работает квота

Портал периодически (например, раз в час) рассчитывает сумму суточных токенов по активным пользователям и отправляет запрос PUT /v1/budget/quota. Роутер выделяет запрошенное количество в пределах доступной ёмкости и ограничений владельца.

Сигнал ёмкости: если granted < requested, в ответе указан параметр limitedBy: "capacity", limitedBy: "owner-max" или limitedBy: "provider-low". Значение "provider-low" означает, что доступная суточная ёмкость была уменьшена вдвое из-за низкого остатка квоты провайдера (≤15%). Это указывает порталу на необходимость замедления фоновых задач или переключения части трафика на внешние модели. Если выделено 0 на сутки, свободной ёмкости нет: MiniMax для проекта выключен до следующего пересчёта, запросы идут на запасные модели роутера или получают 503 budget_exceeded. Это ваш сигнал включить свои прямые запасные модели.

Методы API

МетодАдресЧто делает
PUT/v1/budget/quotaЗапросить или обновить квоту проекта
GET/v1/budget/quotaПолучить текущую квоту, фактические лимиты и остаток нормы
DELETE/v1/budget/quotaСбросить выделенную квоту (вернуться к базовым лимитам)

Пример запроса квоты

bash 
curl -X PUT https://router.example.com/v1/budget/quota \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "day": 20000000,
    "hour": 5000000,
    "user": {
      "day": 1000000,
      "hour": 250000
    },
    "ttlSec": 86400
  }'

Все числа задаются в кэш-взвешенных токенах (положительные целые). Должен быть передан хотя бы один из параметров: day, hour или user. Непереданные параметры сохраняют текущие значения. Время жизни ttlSec по умолчанию составляет 86400 с (24 ч) и ограничивается интервалом от 300 до 604800 с (от 5 мин до 7 дней). По истечении TTL квота автоматически сбрасывается к базовым настройкам.

В ответе GET и PUT /v1/budget/quota в блоке cycle.provider возвращается актуальный статус квоты MiniMax: процент недельного (weeklyRemainingPercent) и интервального (intervalRemainingPercent) остатка, окончание окон (weeklyEnd, intervalEnd) и метка времени опроса fetchedAt с признаком свежести fresh.

Ограничение частоты (Rate Limit)

Запросы PUT /v1/budget/quota ограничены: не чаще одного успешного обновления в 60 секунд для каждого проекта. При более частых запросах возвращается 429 quota_rate_limited с заголовком Retry-After. Запросы GET и DELETE не ограничиваются по частоте.

Как не упереться в лимиты

  • Сжимайте контекст в циклах агентов. Старые результаты инструментов, особенно большие (HTML страниц, логи, выдачу поиска), заменяйте коротким пересказом, а не пересылайте на каждом шаге.
  • Ограничивайте вывод инструментов, например 10–20 тыс. символов на один вызов. Из HTML извлекайте текст до того, как отдавать его модели.
  • Держите начало промпта неизменным (system и первые сообщения). Тогда у провайдера срабатывает кэш и повторный контекст обходится дешевле.
  • Ставьте лимит шагов агента на одно сообщение пользователя и пишите в лог, когда он срабатывает.
  • Для суммаризации берите text-summarize, а не text-high.
  • Задавайте таймауты с запасом. При сбое модели роутер сам переходит на следующую, и ответ может прийти через 20–60 секунд.
